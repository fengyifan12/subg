◆ otPlatDsoAccept()

otPlatDsoConnection* otPlatDsoAccept ( otInstance *  aInstance,
const otSockAddr *  aPeerSockAddr 
)

Is a callback from the DSO platform to indicate an incoming connection request when listening is enabled.

Determines whether or not to accept the connection request. It returns a non-null otPlatDsoConnection pointer if the request is to be accepted, or NULL if the request is to be rejected.

If a non-null connection pointer is returned, the platform layer MUST continue establishing the connection with the peer. The platform reports the outcome by invoking otPlatDsoHandleConnected() callback on success or otPlatDsoHandleDisconnected() callback on failure.

Parameters
[in]aInstanceThe OpenThread instance.
[in]aPeerSockAddrThe socket address (IPv6 address and port number) of the peer requesting connection.
Returns
A pointer to the otPlatDsoConnection to use if to accept, or NULL if to reject.

Requests a connection to be disconnected.

After calling this function, the DSO platform implementation MUST NOT maintain aConnection pointer (platform MUST NOT call any callbacks using this Connection pointer anymore). In particular, calling otPlatDsoDisconnect() MUST NOT trigger the callback otPlatDsoHandleDisconnected().

Parameters
[in]aConnectionThe connection to disconnect
[in]aModeThe disconnect mode (close gracefully or forcibly abort).

void otPlatDsoEnableListening ( otInstance *  aInstance,
bool  aEnable 
)

Starts or stops listening for incoming connection requests on transport layer.

For DNS-over-TLS, the transport layer MUST listen on port 853 and follow RFC 7858.

While listening is enabled, if a connection request is received, the otPlatDsoAccept() callback MUST be called.

Parameters
[in]aInstanceThe OpenThread instance.
[in]aEnableTRUE to start listening, FALSE to stop listening.

◆ otPlatDsoHandleConnected()

void otPlatDsoHandleConnected ( otPlatDsoConnection *  aConnection)

Is a callback from the platform layer to indicate that a connection is successfully established.

It MUST be called either after accepting an incoming connection (otPlatDsoAccept) or after a otPlatDsoConnect() call.

Only after this callback, the connection can be used to send and receive messages.

Parameters
[in]aConnectionThe connection.

Is a callback from the platform layer to indicate that peer closed/aborted the connection or the connection establishment failed (e.g., peer rejected a connection request).

After calling this function, the DSO platform implementation MUST NOT maintain aConnection pointer (platform MUST NOT call any callbacks using this Connection pointer anymore).

Parameters
[in]aConnectionThe connection which disconnected.
[in]aModeThe disconnect mode (closed gracefully or forcibly aborted).

◆ otPlatDsoHandleReceive()

void otPlatDsoHandleReceive ( otPlatDsoConnection *  aConnection,
otMessage *  aMessage 
)

Is a callback from the platform layer to indicate that a DNS message was received over a connection.

The platform MUST call this function only after the connection is successfully established (after callback otPlatDsoHandleConnected() is invoked).

Passes the ownership of the aMessage from the DSO platform layer to OpenThread. OpenThread will free the message when no longer needed.

The aMessage MUST contain the DNS message (starting with DNS header) and not include the length field that may be included in TCP/TLS exchange.

Parameters
[in]aConnectionThe connection on which the message was received.
[in]aMessageThe received message.

◆ otPlatDsoSend()

void otPlatDsoSend ( otPlatDsoConnection *  aConnection,
otMessage *  aMessage 
)

Sends a DSO message to the peer on a connection.

Is used only after the connection is successfully established (after otPlatDsoHandleConnected() callback).

Passes the ownership of the aMessage to the DSO platform layer, and the platform implementation is expected to free the message once it is no longer needed.

The aMessage contains the DNS message (starting with DNS header). Note that it does not contain the the length field that is needed when sending over TLS/TCP transport. The platform layer MUST therefore include the length field when passing the message to TLS/TCP layer.

Parameters
[in]aConnectionThe connection to send on.
[in]aMessageThe message to send.
