9 /*
10 P-256 ECDH implementation
11 =========================
12 
13 How to use
14 ----------
15 Each part generates a key pair:
16  uint8_t my_public_point[64], my_private_key[32];
17  do {
18  generate_random_bytes(my_private_key, 32);
19  } while (!P256_ecdh_keygen(my_public_point, my_private_key));
20 The function generate_random_bytes is a placeholder for calling the system's cryptographically secure random generator.
21 With probability around 1/2^32, the loop will need more than one iteration.
22 
23 The public points are then exchanged, and the shared secret is computed:
24  uint8_t shared_secret[32];
25  if (!P256_ecdh_shared_secret(shared_secret, others_public_point, my_private_key)) {
26  // The other part sent an invalid public point, so abort (it is important to handle this case)
27  } else {
28  // The shared_secret is now the same for both parts and may be used for cryptographic purposes
29  }
30 A safe alternative if one doesn't want to change the following parts of a protocol if the user sends an invalid key is to replace the
31 shared secret with the x coordinate of the own public key (same result as if the remote user sent the basepoint as public key) as follows:
32  uint8_t shared_secret[32];
33  if (!P256_ecdh_shared_secret(shared_secret, others_public_point, my_private_key)) {
34  memcpy(shared_secret, my_public_point, 32);
35  }
36  // The shared_secret is now the same for both parts and may be used for cryptographic purposes
37 
38 About endianness
39 ----------------
40 All parameters (coordinates, scalars/private keys, shared secret) are represented in little endian byte order.
41 Other libraries might use big endian convention, so if this should be used against such a library, make sure all 32-byte values exchanged are reversed.
42 
43 Security
44 --------
45 The implementation runs in constant time (unless input values are invalid) and uses a constant memory access pattern,
46 regardless of the scalar/private key in order to protect against side channel attacks.
47 
48 Stack usage
49 -----------
50 All functions need 1356 bytes available stack size on Cortex-M0 and 1.5 kB on Cortex-M4.
51 
52 */

55 // Calculates scalar * point.
56 // If include_y_in_result == 0, result_point should be an array of size 32 bytes where the resulting x coordinate will be written.
57 // If include_y_in_result != 0, result_point should be an array of size 64 bytes where the resulting x coordinate concatenated with y will be written.
58 // Returns true on success and false on invalid input (see the functions below what defines invalid input).

62 // ECDH keygen
63 // Multiplies the scalar private_key with the curve-defined base point.
64 // The result should be an array of size 64 bytes where the x coordinate concatenated by the y coordinate will be written.
65 // Returns true on success and false if the private_key lies outside the allowed range [1..n-1], where n is the curve order.
66 // If false is returned, the result is not written. (At that point this function can be called again with a new randomized private_key.)

69 // ECDH shared secret
70 // Multiplies the scalar private_key with the other's public point.
71 // The result should be an array of size 32 bytes where the x coordinate of the result will be written (y is discarded).
72 // Returns true on success and false if any of the following occurs:
73 // - the scalar private_key lies outside the allowed range [1..n-1], where n is the curve order
74 // - a public point coordinate integer lies outside the allowed range [0..p-1], where p is the prime for the field used by the curve
75 // - the public point does not lie on the curve
76 // If false is returned, the result is not written.
77 // NOTE: the boolean return value MUST be checked in order to avoid different attacks.
78 bool P256_ecdh_shared_secret(uint8_t result_point_x[32], const uint8_t others_public_point[64], const uint8_t private_key[32]) __attribute__((warn_unused_result));
