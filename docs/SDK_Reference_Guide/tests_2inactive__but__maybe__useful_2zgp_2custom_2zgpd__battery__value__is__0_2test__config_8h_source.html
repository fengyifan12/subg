30 /* 04/09/2014 CR:CX9262:MAJOR
31  *
32  * General notes for all tests:
33  *
34  * Tests should be clear and do not include anything unrelated to this test.
35  * For example, test "Battery value is 0" should send only battery notifications,
36  * no door/window state attribute reports are needed. So function user_action,
37  * define REPORT_COUNT are unneeded and should be deleted. Also, we don't
38  * test security here, so we don't need TEST_SECURITY_LEVEL define and can use
39  * ZB_ZGP_SEC_LEVEL_FULL_WITH_ENC as default. In some tests test_config.h can
40  * be deleted completely.
41  *
42  * Deleting all unnecessary things would help developers maintaining these tests,
43  * because their behaviour becomes more clear.
44  *
45  * Also, tests should be easily verifiable. I mean, we need to provide clear
46  * pass verdict criteria for test executor. For example, for test "Battery
47  * value is 0" I think it would better to send four battery measurements one
48  * after another with some timeout. Values for voltage are 0, 3, 0, 2 in volts.
49  * So, test executor should verify that result of test is two measurements from
50  * gateway to cloud with 3.0 and 2.0 voltage values. It is easy to verify that
51  * measurements with 0 volts are really skipped in this case.
52  *
53  * Another point about verification. Some tests contain pass verdict message
54  * "Test finished. Status OK", but not all of them. Since tests implement test
55  * harness role, they should output pass verdict message. Tests should
56  * output not only "Status OK", but "Status FAILED" messages also. It will
57  * help significantly to the test executor.
58  *
59  * Copy/paste of the same coordinator to all tests seems wrong. It's better to
60  * extract coordinator code to the separate folder and use it in all tests.
61  *
62  * Also, modify readme.txt in tests so they describe actual behaviour of the tests.
63  * Add pass verdict criteria in readme wherever possible.
64  */
